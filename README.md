# CRM + فورم تسجيل العملاء

العميل بيسجل بياناته في الفورم، والبيانات بتوصل على طول للوحة الـ CRM، متقسمة حسب المنطقة والمحافظة والمنصب والأولوية والحالة.

مكتوب بـ PHP وقاعدة بيانات SQLite (ملف واحد)، فبيشتغل على أي استضافة عادية زي Hostinger من غير سيرفر إضافي ومن غير إعداد قاعدة بيانات. متجرب على PHP 7.4 و PHP 8.3.

## الرفع على Hostinger

1. **اعمل subdomain:** من hPanel افتح إعدادات الدومين `orvann.com` ثم Subdomains، واعمل `crm`. خد بالك من الفولدر اللي هيتعمله (غالباً `public_html/crm`).
2. **ارفع الملفات:** افتح File Manager وادخل الفولدر ده، ارفع `crm-upload.zip`، واعمله Extract في نفس الفولدر، وبعدين امسح ملف الـ zip.
   - لازم الملفات تبقى في الفولدر مباشرة: `index.html` و `admin/` و `api/` و `app/` و `data/`، مش جوه فولدر `public` تاني.
   - فعّل إظهار الملفات المخفية في File Manager واتأكد إن `.htaccess` موجود. الملفات دي هي اللي بتحمي كلمة السر وقاعدة البيانات.
3. **SSL:** اتأكد إن `crm.orvann.com` عليه شهادة SSL من hPanel (بتتفعل لوحدها غالباً خلال دقايق).
4. **افتح** `https://crm.orvann.com/admin/` وادخل ببيانات الدخول الموجودة في `app/settings.php`.

### فحص بعد الرفع

| جرّب | المفروض يحصل |
|---|---|
| `https://crm.orvann.com/admin/` | صفحة الدخول من غير رسالة خطأ. لو فيه مشكلة في الاستضافة (SQLite مش مفعّل، فولدر مش قابل للكتابة) هتظهر مكتوبة هناك |
| `https://crm.orvann.com/api/options` | نص JSON فيه القوائم. لو طلع 404 يبقى إعادة كتابة الروابط مش شغالة، واستخدم `https://crm.orvann.com/api/index.php?r=leads` كرابط للموقع |
| `https://crm.orvann.com/app/settings.php` | **403 ممنوع** |
| `https://crm.orvann.com/data/access-check.txt` | **403 ممنوع**. لو اتفتح، اللوحة هتعرض تحذير أحمر، وساعتها متستخدمش النظام قبل ما تتحل |
| سجّل عميل من `https://crm.orvann.com/` | يظهر في اللوحة |

ملفات `.htaccess` اتكتبت بنفس الأوامر اللي موقعك ونظام ORVANN Tasks بيستخدموها على نفس الاستضافة، بس متجربتش على سيرفر Hostinger نفسه، فالجدول ده هو التأكيد.

## إزاي العملاء بيتنظموا

| التصنيف | بيتحدد إزاي |
|---|---|
| **المنطقة** | تلقائي من المحافظة أو الدولة (القاهرة الكبرى، الدلتا، الصعيد، الخليج...) |
| **المحافظة / المنصب / الخدمة** | من قوائم ثابتة، فمفيش كتابة عشوائية تبوّظ التقسيم |
| **الأولوية** | تلقائي: كل اختيار ليه نقاط (المنصب + الخدمة + الميزانية + التوقيت). صاحب شركة عايز الخدمة فوراً بميزانية كبيرة = أولوية عالية. وتقدر تغيرها يدوي من اللوحة |
| **الحالة** | جديد ← تم التواصل ← مهتم ← تفاوض ← تم البيع / غير مهتم |
| **الأرقام** | أي رقم مصري بيتحول لشكل واحد (01xxxxxxxxx) حتى لو اتكتب بأرقام عربي أو بـ +20، وبيظهر جنبه اسم الشبكة. الأرقام الدولية بتتحفظ بـ + وكود الدولة |

**لو العميل سجّل مرتين بنفس الرقم أو نفس الإيميل** مش بيتعمل له سطر جديد. بيتحدث العميل القديم، وبيتسجل في الملاحظات إنه رجع، وبيطلع أول القايمة، وبياخد نقطة زيادة في الأولوية.

العميل لازم يكون له اسم ووسيلة تواصل واحدة على الأقل (موبايل أو إيميل). أي حقل تاني ناقص بيتسجل فاضي، وأي قيمة مش موجودة في القوائم بتتكتب في آخر رسالة العميل بدل ما تضيع.

## اللوحة فيها إيه

- أرقام سريعة: الإجمالي، اللي سجلوا النهارده، الجداد اللي محدش كلمهم، الأولوية العالية
- تصنيفات جانبية بالعدد، وتدوس على أي واحد يفلتر بيه (وتقدر تجمع أكتر من فلتر)
- بحث بالاسم أو الرقم أو الشركة، وفلترة بالتاريخ وترتيب
- صفحة لكل عميل فيها زرار اتصال وواتساب، وتغيير الحالة والأولوية، وملاحظات المتابعة (كل تغيير بيتسجل)
- تصدير Excel بالفلاتر الحالية
- اللوحة بتتحدث لوحدها كل 30 ثانية، وبتنبهك لما يوصل عميل جديد

## ربط orvann.com

فورم Start a Project على الموقع بيبعت نسخة من كل تسجيل للـ CRM من جوه `project.php`. التفاصيل ومرجع الـ API في [INTEGRATION.md](INTEGRATION.md).

لأي موقع تاني، الفورم بتاع الـ CRM نفسه بيتحط في أي صفحة بسطرين:

```html
<div id="crm-form"></div>
<script src="https://crm.orvann.com/embed.js"></script>
```

## الإعدادات

| الملف | فيه إيه |
|---|---|
| [public/app/settings.php](public/app/settings.php) | اسم المستخدم وكلمة السر، مفتاح الربط مع الموقع (`integration_key`)، والمواقع المسموح لها |
| [public/app/config.php](public/app/config.php) | القوائم: المحافظات والمناطق، المناصب، الخدمات، الميزانيات، ونقاط كل اختيار، وحدود الأولوية |

عدّل الملف وارفعه مكان القديم، والفورم واللوحة بيتحدثوا لوحدهم.

- **غيّر كلمة السر قبل الرفع** في `settings.php`.
- الـ `id` في القوائم هو اللي الموقع بيبعته، فمتغيرهوش بعد الربط. غيّر الـ `name` والـ `weight` براحتك.

## النسخ الاحتياطي والتحديث

- **كل العملاء في ملف واحد:** `data/crm-….sqlite` على السيرفر. نزّل نسخة منه من File Manager كل فترة.
- **لما ترفع تحديث للكود:** ارفع كل حاجة **ما عدا** فولدر `data/` وملف `app/settings.php`، عشان العملاء وكلمة السر ميتمسحوش.

## التجربة على جهازك

محتاج PHP 7.4 أو أحدث فيه `pdo_sqlite` و `mbstring`:

```bash
php -S localhost:3000 -t public dev-router.php
```

الفورم على http://localhost:3000/ واللوحة على http://localhost:3000/admin/. فولدر `local-data/` فيه بيانات التجربة المحلية ومبيترفعش.
